## 2. เปิดครั้งแรก (`ui/onboarding/`)

- ขอสิทธิ์ตำแหน่ง แยก 3 สถานะ: **แม่นยำ / โดยประมาณ / ไม่ให้** — "โดยประมาณ" นำทางไม่ได้
  (Android 12+ ให้ผู้ใช้เลือกได้) จึงถือว่ายังไม่พร้อม
- ดาวน์โหลดแผนที่เฉพาะ bbox ของวิทยาเขต แล้วเด้งแจ้งเมื่อพร้อมใช้ออฟไลน์ (README F1)
- `MainActivity` อ่านค่า `offlineMapReady` จาก DataStore เพื่อเลือกหน้าแรก —
  ระหว่างอ่านจะโชว์จอเปล่าแวบเดียวแทนการเปิดผิดหน้าแล้วกระโดด

## 3. เลือกจุดหมาย (`ui/poi/PoiListScreen.kt`)

- จุดที่ **นำทางไปไม่ได้** (ไม่มีเส้นทางเชื่อมถึง) **ยังแสดงอยู่ แต่มีป้ายบอก** — ตั้งใจไม่ซ่อน
  เพราะซ่อนแล้วผู้ใช้จะหาสถานที่ที่รู้ว่ามีอยู่จริงไม่เจอ ป้ายนั้นชี้ไปที่ทางแก้จริง คือไปเดินเก็บเส้นทางที่ขาด

## 5. โหมดสำรวจพิกัด POI (`ui/survey/`)

- ยืนที่จุดจริงกลางแจ้ง → รอความแม่นยำ < 10 ม. → กดเริ่ม → เฉลี่ยหลาย fix ด้วย **median**
  (`survey/PointSurveySession.kt` ตัวเดียวกับหน้าเก็บพิกัด GPS) → บันทึกเป็น POI แล้วส่งออก `pois.geojson`
- **เก็บเฉพาะจุด** — เดิมเคยมีแท็บเก็บเส้นทางอยู่ในหน้านี้ แต่ย้ายไป `ui/pathlog/` แล้ว
  เพราะเส้นทางเป็น "ค่าที่วัดได้" ไม่ควรอยู่หน้าเดียวกับฟอร์มชื่ออาคาร/คณะ (กฎข้อ 9 ใน `CLAUDE.md`)

## 6. ข้อมูล GPS — Debug (`ui/debug/`)

หน้าซ่อนสำหรับไล่ปัญหา "หมุดไม่ตรง" ว่าผิดที่ GPS หรือผิดที่ข้อมูลแผนที่
เปิดด้วยการกด **"เวอร์ชัน"** ในหน้าตั้งค่า 7 ครั้ง แล้วจะมีเมนู "ข้อมูล GPS (Debug)" โผล่ขึ้นมา

แสดง: provider · ตำแหน่ง · ความแม่นยำ · ดาวเทียม (ใช้/เห็น) · ความสูง (ทรงรี WGS84) ·
ความเร็ว · ทิศทาง · อายุของ fix · **ระยะถึงเส้นทางใกล้สุด** · ตำแหน่ง **ดิบ / หลังกรอง**
(`core/geo/GpsKalmanFilter.kt`) · จำนวน fix ที่ถูกทิ้ง

> อ่านค่าให้เป็น: **ความแม่นยำดี แต่ระยะถึงเส้นทางไกลมาก = ข้อมูลแผนที่ผิด ไม่ใช่ GPS**
> ให้ไปเดินเก็บเส้นทางทับ อย่าไปจูน GPS
