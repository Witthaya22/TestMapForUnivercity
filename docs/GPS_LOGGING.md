# GPS_LOGGING.md — ระบบเก็บพิกัด GPS (GPS Point Log)

**"เก็บพิกัด GPS"** (F11b) คือระบบเก็บ **ค่าที่วัดได้จากเครื่องรับ GPS**
ยืนตรงจุดที่ต้องการ กดเก็บ แล้วส่งออกเป็นไฟล์ GeoJSON หรือ CSV

มี **2 โหมดให้เลือก** เก็บลง**ชุดข้อมูลเดียวกัน** และส่งออกไฟล์เดียวกัน

> เข้าใช้งาน: **ตั้งค่า → (หมวดผู้ดูแล) → เก็บพิกัด GPS** (โหมดแผนที่)
> หรือ **เก็บพิกัด GPS (โหมดตัวเลข ไม่มีแผนที่)**
> โค้ด: `ui/gpslog/` · `data/model/GpsPoint.kt` · `data/geojson/GpsPointExporter.kt`

---

## 0. สองโหมด ชุดข้อมูลเดียว

| | **โหมดแผนที่** (`GpsLogScreen`) | **โหมดตัวเลข** (`GpsReadoutScreen`) |
|---|---|---|
| เห็นอะไร | แผนที่ + หมุดตัวเอง + วงความคลาดเคลื่อน + รอยทางที่เดิน + จุดที่เก็บแล้ว | ตัวเลขจากเครื่องรับล้วน ๆ ครบทุกค่า |
| เหมาะกับ | เดินสำรวจ ต้องรู้ว่าตัวเองอยู่ตรงไหนบนมอ | ยืนเก็บทีละจุดที่รู้ตำแหน่งอยู่แล้ว |
| ข้อดี | ตรวจเจอทันทีว่าหมุดไปโผล่ในตึกผิดหลัง | เปิดเร็ว กินแบตน้อย (ไม่ต้อง render แผนที่) |
| ค่าเพิ่มที่เห็น | — | ความเร็ว · ทิศทาง · อายุ fix ล่าสุด · จำนวน fix ที่ถูกทิ้ง |
| บันทึกเป็น | `captureMode: "map"` | `captureMode: "readout"` |

**ทั้งสองโหมดใช้:** ตาราง `gps_point` เดียวกัน · เลขรหัส `P001, P002…` ชุดเดียวต่อกัน ·
ตัวเฉลี่ย `PointSurveySession` ตัวเดียวกัน · ไฟล์ส่งออกแบบเดียวกัน
ตอนส่งออกเลือกได้ว่าเอา **ทั้งหมด / เฉพาะโหมดแผนที่ / เฉพาะโหมดตัวเลข**

**ทำไมต้องจำว่าเก็บจากโหมดไหน:** สองโหมดไม่ใช่หลักฐานคุณภาพเท่ากัน
โหมดแผนที่คนเก็บจะเห็นทันทีว่าหมุดไปโผล่ผิดที่แล้วเก็บใหม่ได้ โหมดตัวเลขไม่เห็น
อีกหลายเดือนถัดมานี่คือความต่างระหว่าง "ค่าที่มีคนตรวจแล้ว" กับ "ค่าที่แค่กดเก็บ"
ซึ่งไม่มีใครจำได้ถ้าไฟล์ไม่ได้เขียนไว้

> โค้ดของสองหน้าจอใช้ ViewModel ตัวเดียวกัน (`GpsLogViewModel` รับ `captureMode`)
> และส่วน UI ที่ใช้ร่วมกันอยู่ใน `GpsLogComponents.kt` — เพื่อไม่ให้หน้าจอที่สอง
> ค่อย ๆ กลายเป็นสำเนาที่เพี้ยนไปจากหน้าจอแรก

> จุดที่เก็บที่นี่ไม่เข้ากราฟ routing จึงนำทางตามไม่ได้ ถ้าต้องการทำทางเดินในที่ที่ไม่มีทาง
> ให้ใช้ **เดินเก็บเส้นทาง** (`ui/pathlog/`) แล้วใช้หน้านี้เสริมเฉพาะจุดสำคัญ

## 1. ระบบนี้ต่างจาก "โหมดสำรวจพิกัด" (Surveyor Mode) ยังไง

โปรเจกต์นี้มี **2 ระบบที่ใช้ GPS เก็บจุด** และตั้งใจให้แยกกัน ห้ามรวม

| | โหมดสำรวจพิกัด (`ui/survey/`) | เก็บพิกัด GPS (`ui/gpslog/`) |
|---|---|---|
| ตอบคำถามว่า | "ประตูอาคารนี้อยู่ตรงไหน" | "เครื่องวัดได้ค่าเท่าไร ตอนนั้นแม่นแค่ไหน" |
| ผลลัพธ์กลายเป็น | **POI** บนแผนที่ (มีชื่อ / หมวดหมู่ / ใช้นำทางได้ทันที) | **ค่าที่วัดได้** เฉย ๆ ไม่เข้ากราฟ routing ไม่ขึ้นเป็นหมุดสถานที่ |
| หน้าจอ | ฟอร์ม + ตัวเลข | เลือกได้ 2 โหมด: **แผนที่** (เห็นตัวเองเดิน) หรือ **ตัวเลข** (ดู §0) |
| ไฟล์ที่ส่งออก | `pois_surveyed.geojson` (มี `name`, `category`, …) | `gps_points_*.geojson` / `.csv` (**มีแต่ค่าการวัด**) |
| ตารางใน Room | `poi` | `gps_point` |

**เหตุผลที่แยก:** ไฟล์ที่ส่งออกจากระบบนี้ต้องเป็น *ข้อมูลดิบของการวัด* ล้วน ๆ
ไม่มี "จุดคณะวิศวะ" "จุดแผนกไอที" ปนมา เพราะชื่อและหมวดหมู่เป็นสิ่งที่คนใส่ทีหลังและเปลี่ยนได้
แต่ค่าที่เครื่องวัดได้ ณ วินาทีนั้นเปลี่ยนไม่ได้ และเป็นสิ่งเดียวที่เอาไปตรวจสอบย้อนหลังได้จริง
ถ้าปนกัน ไฟล์จะกลายเป็น "แผนที่ที่ทำไม่เสร็จ" แทนที่จะเป็น "ชุดข้อมูลการวัด"

ทั้งสองระบบ **ใช้ตัวเฉลี่ยพิกัดตัวเดียวกัน** คือ `survey/PointSurveySession.kt`
(median ไม่ใช่ mean — ดู §4) จึงมีสูตรเดียว เขียน unit test ที่เดียว

## 2. วิธีใช้ในสนาม

1. ออกไป **กลางแจ้ง** เปิดหน้าจอ รอจนการ์ดบนสุดขึ้นค่าความคลาดเคลื่อน (ไม่ใช่ "กำลังหาสัญญาณ")
   เย็นเครื่อง + ไม่มีเน็ต อาจรอ 30–90 วินาที เป็นเรื่องปกติ (ดู `ACCURACY.md` A3)
2. เดินไปยืนตรงจุดที่ต้องการ — **บนแผนที่จะเห็นหมุดฟ้าเคลื่อนตาม และมีเส้นประบอกทางที่เพิ่งเดินมา**
   กล้องจะตามหมุดให้เอง ถ้าเลื่อนแผนที่เองเมื่อไร กล้องจะหยุดตาม กดปุ่ม 🎯 เพื่อกลับไปตามต่อ
3. **ยืนนิ่ง** แล้วกด **"เก็บจุดนี้"** — แอปจะเก็บ fix 30 ครั้ง (~30 วินาที) แล้วหาค่ากลาง
   ระหว่างนี้จะบอกจำนวนครั้งที่เก็บได้ / ที่ทิ้งไป และค่าคลาดเคลื่อนเฉลี่ยสด ๆ
   ถ้ารีบก็กด "หยุดแล้วใช้ค่าที่วัดได้" ได้ ค่าที่ได้จะบันทึกว่าใช้กี่ครั้ง (`sampleCount`)
4. ใส่หมายเหตุถ้าต้องการ (ไม่ใส่ก็ได้) แล้วกด **"บันทึกจุดนี้"** → ได้รหัส `P001`, `P002`, … ตามลำดับ
5. จุดที่เก็บแล้วจะโผล่บนแผนที่ทันที **สีบอกคุณภาพ**
   🟢 เขียว ≤ 5 ม. · 🟠 ส้ม ≤ 10 ม. · 🔴 แดง > 10 ม.
   แตะหมุดเพื่อดูค่าทั้งหมด แก้หมายเหตุ หรือลบทิ้ง
6. เสร็จแล้วกด **"ส่งออก"** มุมบนขวา → เลือก GeoJSON หรือ CSV → เลือกที่เก็บไฟล์เอง (SAF ไม่ต้องขอสิทธิ์)

**ก่อนกด "ลบจุดทั้งหมด" ให้ส่งออกไฟล์เก็บไว้ก่อนเสมอ** ลบแล้วกู้ไม่ได้

## 3. ค่าที่เก็บและส่งออก

ทุกชื่อฟิลด์ **ตรงกันหมด** ตั้งแต่ property ใน Kotlin (`data/model/GpsPoint.kt`),
คอลัมน์ในตาราง `gps_point`, key ใน GeoJSON, ไปจนถึงหัวคอลัมน์ใน CSV
(ตั้งใจให้ไล่ตามได้โดยไม่ต้องมีตารางแปลงชื่อ)

| ฟิลด์ | หน่วย / รูปแบบ | ความหมาย | ทำไมต้องมี |
|---|---|---|---|
| `code` | `P001` | รหัสวิ่งตามลำดับที่เก็บ | ไว้จดใส่สมุดคู่กับภาคสนาม เลขจะไม่ถูกใช้ซ้ำแม้ลบจุดทิ้ง |
| `lat` / `lon` | องศา WGS84 ทศนิยม 7 ตำแหน่ง (~1 ซม.) | พิกัด | ค่ากลาง (median) ของ fix ที่รับมา |
| `accuracyMeters` | เมตร | **ความคลาดเคลื่อนแนวราบ** ที่ Android รายงาน (รัศมี ความเชื่อมั่น 68%) | ตัวตัดสินว่าจุดนี้ใช้ได้ไหม — ค่าเฉลี่ยของ fix ที่รับ |
| `elevationMeters` | เมตร | ความสูง**เทียบทรงรี WGS84** ไม่ใช่ระดับน้ำทะเล | มีดีกว่าไม่มี แต่คลาดเคลื่อนกว่าแนวราบ 2–3 เท่า อย่าเอาไปทำ contour |
| `verticalAccuracyMeters` | เมตร | ความคลาดเคลื่อนแนวดิ่ง | Android รายงานตั้งแต่ API 26 เครื่องเก่ากว่านั้นเป็น `null` |
| `satellitesUsed` | ดวง | **ดาวเทียมที่ใช้คำนวณ fix จริง** | < 4 ดวง = ค่าไม่น่าเชื่อถือ (3D fix ต้องการอย่างน้อย 4) |
| `satellitesVisible` | ดวง | ดาวเทียมที่เครื่องมองเห็นทั้งหมด | เห็นเยอะแต่ใช้ได้น้อย = โดนอาคาร/ต้นไม้บัง |
| `sampleCount` | ครั้ง | จำนวน fix ที่เอามาเฉลี่ย | 30 = เก็บครบ, น้อยกว่านั้น = กดหยุดเอง หรือสัญญาณขาด |
| `rejectedCount` | ครั้ง | fix ที่ถูกทิ้งเพราะคลาดเคลื่อนเกิน 15 ม. | ค่าสูง = จุดนั้นสัญญาณแย่จริง ควรกลับไปวัดซ้ำ |
| `spreadMeters` | เมตร | ระยะจากค่าที่ได้ ถึง sample ที่ไกลที่สุด | **ค่าความซ้ำได้จริง** — ถ้า `accuracy` ดีแต่ `spread` สูง แปลว่าเครื่องโม้ |
| `durationSeconds` | วินาที | เวลาที่ยืนวัด (fix แรกถึง fix สุดท้าย) | คู่กับ `sampleCount` บอกว่าสัญญาณขาดช่วงไหม |
| `recordedAt` | ISO-8601 มี offset เช่น `2026-09-20T14:32:05+07:00` | เวลาที่เก็บ | ไว้ย้อนดูสภาพอากาศ/เวลาของวัน และเรียงลำดับการสำรวจ |
| `captureMode` | `map` / `readout` | เก็บจากหน้าจอไหน | บอกว่าตอนเก็บมีแผนที่ให้ตรวจสอบด้วยหรือเปล่า — ดู §0 |
| `note` | ข้อความไทยได้ | หมายเหตุที่คนใส่ | ฟิลด์**เดียว**ที่แก้ทีหลังได้ นอกนั้นคือค่าที่วัดมา ห้ามแก้ |

### ค่าที่ตั้งใจ *ไม่* เก็บ

| ไม่เก็บ | เหตุผล |
|---|---|
| ชื่อสถานที่ / หมวดหมู่ / คำอธิบาย | นั่นคือหน้าที่ของ POI ไม่ใช่ของค่าการวัด — ถ้าจะทำจุดสถานที่ ใช้โหมดสำรวจพิกัด |
| HDOP / PDOP | `android.location.LocationManager` ไม่มี API ให้ ต้อง parse NMEA ดิบเอง และ `accuracyMeters` ก็คือค่าที่ Android คำนวณแทนให้อยู่แล้ว |
| ความเร็ว / ทิศทาง | ตอนเก็บจุดต้องยืนนิ่ง ค่าพวกนี้จึงเป็นศูนย์หรือสัญญาณรบกวนเสมอ (โหมดตัวเลขแสดงให้ดูสด ๆ เพื่อเช็กว่าเครื่องนิ่งจริง แต่ไม่บันทึกลงไฟล์) |
| พิกัดดิบทุก fix ทั้ง 30 ครั้ง | เก็บแล้วไฟล์บวมโดยไม่ได้ใช้ — `sampleCount` + `spreadMeters` + `rejectedCount` สรุปคุณภาพได้ครบแล้ว |

## 4. ทำไมใช้ median ไม่ใช่ mean

ความคลาดเคลื่อนของ GPS **ไม่สมมาตร** สัญญาณสะท้อนผนังอาคาร (multipath) 2–3 ครั้ง
ลากค่าเฉลี่ยเลื่อนไปหลายเมตร แต่ค่ากลางไม่สนใจมันเลย
`PointSurveySession` จึงใช้ median ทั้ง latitude, longitude, ความสูง และจำนวนดาวเทียม
(จำนวนดาวเทียมใช้ median ด้วย เพราะสัญญาณตกวูบวินาทีสุดท้ายไม่ควรกลายเป็นค่าที่บันทึก)

fix ที่คลาดเคลื่อนเกิน **15 ม.** ถูกทิ้งตั้งแต่ต้น (`DEFAULT_MAX_ACCURACY_M`)
เข้มกว่าเกณฑ์ตอนนำทาง (25 ม.) เพราะพิกัดที่เก็บไว้จะถูกใช้ต่อไปอีกหลายปี

## 5. รูปแบบไฟล์ที่ส่งออก

ชื่อไฟล์ตั้งต้น `gps_points_YYYYMMDD_HHmm.<นามสกุล>` — เวลาที่ส่งออกติดไปกับชื่อไฟล์เลย

### 5.1 GeoJSON (`.geojson`)

`FeatureCollection` ของ `Point` ตาม RFC 7946 เป๊ะ ไม่มี foreign member เพิ่มที่ระดับ collection
(ตัวอ่านที่เข้มงวดมีสิทธิ์ปฏิเสธไฟล์ที่ใส่ของแปลกปลอม) เปิดใน QGIS / umap ได้ตรง ๆ

```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "geometry": { "type": "Point", "coordinates": [101.3529617, 14.1610243] },
      "properties": {
        "code": "P001",
        "accuracyMeters": 4.3,
        "elevationMeters": 61.4,
        "verticalAccuracyMeters": 8.5,
        "satellitesUsed": 11,
        "satellitesVisible": 23,
        "sampleCount": 30,
        "rejectedCount": 2,
        "spreadMeters": 3.4,
        "durationSeconds": 31,
        "recordedAt": "2026-09-20T14:32:05+07:00",
        "captureMode": "map",
        "note": ""
      }
    }
  ]
}
```

> ⚠️ `coordinates` เรียง **`[lon, lat]`** เสมอ ที่ปราจีนบุรี = `[101.x, 14.x]`
> ค่าที่ไม่มี (เช่นเครื่องไม่รายงานความสูง) เขียนเป็น `null` **ไม่ใช่ตัดคีย์ทิ้ง**
> เพื่อให้แยกออกว่า "เครื่องไม่รายงาน" กับ "ไฟล์นี้ไม่มีคอลัมน์นั้น"

### 5.2 CSV (`.csv`)

คอลัมน์เรียงตาม `GpsPointExporter.CSV_HEADER` — เหมือน GeoJSON ทุกฟิลด์
บวก `lat` / `lon` แยกเป็นคอลัมน์

```
code,lat,lon,accuracyMeters,elevationMeters,verticalAccuracyMeters,satellitesUsed,
satellitesVisible,sampleCount,rejectedCount,spreadMeters,durationSeconds,recordedAt,
captureMode,note
```

- ขึ้นต้นไฟล์ด้วย **UTF-8 BOM** และจบบรรทัดด้วย **CRLF** — ไม่งั้น Excel บน Windows
  อ่านหมายเหตุภาษาไทยเป็นตัวยึกยือ
- ค่าที่มี `,` หรือ `"` ถูกครอบ quote และ escape ตาม RFC 4180 (มี unit test คุม)
- ค่าที่ไม่มี = ช่องว่าง ไม่ใช่ `0` (0 เมตรกับ "ไม่รู้" คนละเรื่องกัน)

### 5.3 เอาไฟล์ไปใช้ต่อ

- **QGIS**: ลาก `.geojson` ลงหน้าต่างได้เลย ตั้งสีตาม `accuracyMeters` เพื่อดูว่าโซนไหนสัญญาณแย่
- **Excel / Google Sheets**: เปิด `.csv` ตรง ๆ
- **เอาไปทำ POI**: ไฟล์นี้ **ไม่ใช่** `pois.geojson` เอาไปวางทับไม่ได้
  ต้องเติม `id` / `name` / `category` เองก่อน (ดู `DATA_FORMAT.md` ข้อ 2)
  ซึ่งเป็นการตัดสินใจของคน ไม่ใช่ของเครื่อง — จึงตั้งใจให้เป็นขั้นตอนแยก

## 7. ถ้าจะแก้ต่อ อ่านตรงนี้ก่อน

- **จะเพิ่มหน้าจอเก็บค่าอันที่ 3** อย่าเขียน ViewModel ใหม่ ให้เพิ่มค่าใน `GpsCaptureMode`
  แล้วส่งเข้า `GpsLogViewModel` ผ่าน factory ใหม่ ส่วน UI ที่ใช้ซ้ำได้อยู่ใน `GpsLogComponents.kt`
  (อย่าลืมเขียน migration เพิ่มไหม — ไม่ต้อง เพราะ `captureMode` เก็บเป็น string อยู่แล้ว
  ค่าที่บิลด์เก่าไม่รู้จักจะอ่านเป็น `map`)
- **จะเพิ่มฟิลด์ใหม่** ต้องแก้ 5 ที่ให้ชื่อตรงกัน: `GpsPoint` → `GpsPointEntity` (+ migration ใหม่,
  DB version +1) → `GpsPointExporter` (ทั้ง GeoJSON และ `CSV_HEADER`) → sheet ใน `GpsLogScreen`
  → ตารางใน §3 ของเอกสารนี้ แล้วเพิ่ม assert ใน `GpsPointExporterTest`
- **อย่าเอาฟิลด์ที่บรรยาย "สถานที่" เข้ามา** (ชื่อ, หมวดหมู่, คณะ, อาคาร) นั่นคือ POI
  ถ้ามีคนขอ ให้ทำเป็นปุ่ม "สร้าง POI จากจุดนี้" ที่เขียนลงตาราง `poi` แทน — คนละตาราง คนละไฟล์
- **อย่าให้จุดที่เก็บเข้ากราฟ routing** `RouteGraphBuilder` อ่านจาก `paths.geojson` + ตาราง `walk_path`
  เท่านั้น การวัดจุดไม่ใช่การบอกว่าเดินผ่านตรงนั้นได้
- **ความสูงจาก GPS เป็นค่าเทียบทรงรี** ถ้าจะแปลงเป็นระดับน้ำทะเล (MSL) ต้องมีโมเดล geoid (EGM96/EGM2008)
  ซึ่งต้องฝังตารางมาด้วย — ยังไม่ทำ และ UI ก็เขียนกำกับไว้แล้วว่าเป็นค่าเทียบทรงรี
- `rememberMapViewWithLifecycle()` จำเป็นเสมอเมื่อใช้ `MapView` ไม่งั้น renderer รั่ว
- ชั้นแผนที่ที่มีตัวหนังสือต้องใช้ `Style.labelFontStack()` (อยู่ใน `MapLayerManager.kt`)
  ห้าม hardcode ชื่อฟอนต์ ไม่งั้นพอออฟไลน์ตัวหนังสือหายหมด
